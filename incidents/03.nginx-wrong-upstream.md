## Симптом (что произошло)
При открытии http://localhost/users?limit=3 открывалась Grafana вместо данных из Базы Данных. В браузере перекидывало на /login и открывалась страница входа Grafana.
В Postman приходил 302 Found, а Server стоял nginx.

## Предмет проверки и порядок действий
1. http://localhost/users?limit=3 — прямое открытие Nginx (порт 80 HTTP, учебный стенд без сертификата)
2. cat default.conf — проверяем конфиг Nginx.


## Что не подтвердилось
Исключена поломка pgapi работает в штатном режиме. Проверено через Postman и браузер http://localhost:3000/users?limit=3
Grafana работает штатно, поломка исключена. (http://localhost:3002 — порт 3002 на Windows)

## Причина инцидента
После proxy_pass в default.conf идет http://grafana:3000, вместо http://pgapi:3000.
Grafana работает в той же сети my-net, по этой причине Nginx её находит и пересылает запрос на Grafana (поиск имени контейнера в одной сети)

## Как устранил инцидент
1. nano default.conf
2. Вписал http://pgapi:3000
   location / {
       proxy_pass http://pgapi:3000;
3. docker exec nginx nginx -t
4. docker exec nginx nginx -s reload
5. В Postman http://localhost/users?limit=3 - код 200 OK. В браузере выдает записи с БД.


## Как избежать инцидент в будущем
- Алерт на правильную отдачу ответа тому или иному сайту. (на стенде нет возможности такое сделать)
- Проверка конфига после любой правки. В нашем случае требовалось проверить http://localhost/users?limit=3
