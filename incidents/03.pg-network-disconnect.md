## Симптом (что произошло)
Postman - код 503, curl -I http://localhost:3000/users - код 503

## Предмет проверки и порядок действий
1. curl -I http://localhost:3000/users — 503
2. curl -I http://localhost:80/users — 503
3. docker ps -a — статус всех контейнеров Up, ничего подозрительного
4. docker logs pgapi — "could not translate host name "pg" to address"
5. docker network inspect my-net — pg в списке нет
6. В DBeaver:
SELECT count(*)
FROM users
_______
400,000

## Что не подтвердилось
DBeaver - БД работает штатно и отдает запросы. Исключена поломка БД. DBeaver идёт на порт от хоста и не зависит от сети (my-net). А pgapi ходит к базе именно по имени внутри сети
Nginx - при curl -I http://localhost:80/users — строка Proxy-Status: PostgREST; error=PGRST000, проблема в pgapi, не в Nginx

## Причина инцидента
В логах pgapi "could not translate host name "pg" to address". Контейнер не может подключиться к БД (pg). Pg не состоял в my-net, pgapi не смог превратить pg в адрес, отсюда 503.
В docker network inspect my-net База Данных pg не была обнаружена в сети my-net

## Как устранил инцидент
docker network connect my-net pg. 
После подключения контейнера к сети my-net в Postman код 200, так же в curl -I http://localhost:3000/users 200 OK и curl -I http://localhost:80/users 200 OK

## Как избежать инцидент в будущем
Контейнеры, которые обращаются друг к другу по имени, должны быть в одной сети, стоит проверять списком docker network inspect после создания или любых изменений контейнера. При создании контейнера требуется ввести флаг --network my-net
