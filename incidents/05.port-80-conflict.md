## Симптом (что произошло)
Запрос на Nginx в браузере http://localhost/users выдал код ошибки 404. Алерт Firing nginx_up = 0

Все остальные службы работают в штатном режиме.

## Предмет проверки и порядок действий
1. `docker ps -a` — новый контейнер web_tmp. nginx статус Exited (0)
2. Освободил порт 80 и запустил nginx, вышел с Exited (1).
3. `docker logs nginx` — host not found in upstream "pgapi" in /etc/nginx/conf.d/default.conf:9
4. `cat default.conf`, `cat nginx.conf` — изменений не обнаружено.

## Что не подтвердилось
Поломка pgapi, базы данных, алерта, grafana не подтвердились. — Запрос на http://localhost:3000/users — pgapi через браузер, запрос проходит, следовательно база данных работает, так же проверил БД через DBeaver — работает без проблем. Стенд мониторинга в Grafana работал штатно

## Причина инцидента
1. Появился новый контейнер с Nginx под именем web_tmp и занял порт 80.

   Ошибку 404 вернул чужой Nginx с настройками по умолчанию. 5** не было, потому что чужому Nginx не нужен был бэкенд, ему не к кому было обращаться.

2. Родной nginx был остановлен Exited (0), по этой причине порт 80 освободился и его занял чужой контейнер. Кто остановил родной контейнер и запустил чужой - неизвестно. 

   После перезапуска nginx — статус Exited (1), был вне сети my-net и не нашел контейнер по имени pgapi. Вывод, что nginx был вне сети my-net, сделан по трём признакам: в логе nginx не нашёл имя pgapi; pgapi при этом работал (http://localhost:3000/users отвечал); после `docker network connect my-net nginx` контейнер запустился.
   Причина выпадения из сети my-net не установлена.

4. Экспортер не смог получить данные от nginx потому что сервер был остановлен, поэтому nginx_up = 0 Firing.

## Как устранил инцидент
1. Остановил web_tmp: `docker stop web_tmp`
2. Удалил web_tmp: `docker rm web_tmp`
3. `docker network connect my-net nginx` — подключил контейнер к сети.
4. `docker start nginx` — работа сервера восстановлена, http://localhost/users в браузере Windows — отдает таблицу users

Алерт вернулся к Normal.

## Как избежать инцидент в будущем
- После запуска или измнения контейнеров проверить подключен ли они к нужной сети `docker network inspect my-net` (контейнер должен быть запущен, остановленные в списке не видны)
- Перед установкой нового контейнера следует проверять занятые порты во избежании конфликтов.
